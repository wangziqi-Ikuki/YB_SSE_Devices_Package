# YB 合成工站 PLC 与上位机技术说明

## 1. 文档目的和范围

本文说明 YB 固态电解质合成工站的两套上位机形态、PLC 通讯协议、运行流程和开发方式。

- **旧 Qt 上位机**：`ybsolidexperiment.exe` 及其源码。它直接用 Qt `QModbusTcpClient` 连接 PLC，是现场已经使用过的参考实现。
- **Uni-Lab OS 上位机**：OS 调度工作流，YB 设备包通过 Modbus TCP 直接向 PLC 写命令、读状态。当前项目的目标是这一种方式。
- **PLC/HMI**：汇川 AutoShop PLC 工程和威纶通 HMI。PLC 内部完成机器人、天平、扫码、舱门和互锁时序；HMI 可用于现场手动操作、状态查看和调试。

本文只描述软件逻辑和协议，不启动上位机、OS、PLC 或真实机械设备，也不替代现场安全操作规程。

事实来源按优先级使用：

1. `HANDOFF.md` 中列出的 PLC 工程和通讯点表；
2. 设备包的 `protocol/yb_synthesis_modbus.yaml` 与 `protocol/upper_pc_modbus.csv`；
3. 旧 Qt 上位机的 `plcmodbusclient.cpp`、`maindialog.cpp`；
4. 当前 OS 设备包代码和已发布工作流合同。

## 2. 系统架构

```text
操作员
  │ 选择配方、托盘、坩埚、槽位和工艺参数
  ▼
Uni-Lab OS 工作流
  │ 调度、人工确认、任务记录、物料记账
  ▼
YB 原子工站 / Modbus 控制器
  │ 编码寄存器、写入命令、轮询状态、解码结果
  ▼
Modbus TCP
  │ Holding Registers，40001 起始
  ▼
汇川 PLC
  │ SBR_300 主流程和各专项流程
  ├─ 机器人：取放托盘、坩埚、料瓶
  ├─ 扫码与天平：扫码、开关天平门、称粉
  ├─ 加样/加珠机构
  ├─ 声共振、马弗炉、焦耳热
  └─ 门、急停、光栅和设备互锁
```

旧 Qt 上位机和 OS 设备包都使用同一组 PLC 寄存器。旧 Qt 程序不是 OS 运行的前置服务；OS 直连模式下，旧 Qt 程序可以关闭。旧 Qt 源码仍然是理解 PLC 报文和现场数据文件的重要参考。

旧 Qt 上位机的典型操作链路是：

1. 程序启动后加载 `recipes\*.json` 和 `rack\rackdata.json`，建立配方列表和物料状态表；
2. 操作员选择配方、添加槽位，并在生成 TASK 弹窗中选择托盘、坩埚、是否有加珠瓶和球磨珠数量；
3. 界面把每个槽位的配方和参数组合成内部 `TaskData`，再根据动作类型组装 40001 起始的寄存器块；
4. `requestSendTask()` 先保存当前任务，状态轮询确认 PLC 空闲或上一个动作已经结束后，`sendTask()` 才发送命令；
5. 程序每约 1 秒读取 `40100`～`40116`，把 `0/1/2/3` 转成未执行、执行中、完成、失败，并更新界面；
6. 命令 3 完成后，额外读取 `40120`～`40189`，把实际重量、加样结果和扫码内容写回任务页面；
7. 上料完成确认、舱门关闭等操作使用 `40090`、`40091`、`40096` 等控制寄存器，不与命令号寄存器混淆。

这套链路解释了旧软件为什么只需要让操作员填写少量业务参数：物料位置、寄存器布局和动作编码都由 Qt 客户端内部完成。OS 设备包把同一逻辑拆成了配方目录、目录校验、原子动作和工作流节点，以便把人工确认、资源记账和运行记录纳入 OS。

## 4. PLC 通讯基础

### 4.1 连接参数

设备包真机图当前配置为：

```json
{
  "simulation": false,
  "business_simulation": false,
  "ip": "192.168.1.10",
  "port": 502,
  "unit_id": 1
}
```

这些是部署配置，不等于现场已经完成验证。真实运行前仍必须现场确认：

- PLC 实际 Modbus TCP 端口；
- PLC 实际 Unit ID/从站号；
- PLC 是否处于允许远程自动运行的状态；
- 机器人、门、光栅、急停和伺服互锁是否满足。

旧 Qt 客户端把 Holding Register 标签转换为 `标签 - 40001` 的零基偏移，并在 Qt 请求中使用 server/Unit ID `1`。设备包使用相同的地址约定。通讯类型是 Holding Registers，常用功能码为读保持寄存器 `03` 和写多个保持寄存器 `16`。

### 4.2 上位机命令寄存器

`40001`（PLC 内部对应 D0）是命令号。命令发送后，PLC 根据命令号进入互斥的自动流程；同一时刻不能并行执行互斥动作。

| 命令号 | 名称 | 作用 | 完成状态 |
| ---: | --- | --- | --- |
| 1 | 下料 | 从加样料架移除物料/加样头 | `40100` |
| 2 | 上料 | 向加样料架补充物料/加样头 | `40101` |
| 3 | 加粉加珠 | 扫码、称粉、加粉、加珠、回放坩埚 | `40102` |
| 4 | 烧结上料 | 向马弗炉/焦耳热下发工艺并上料 | `40103` |
| 5 | 烧结下料 | 从马弗炉/焦耳热取料 | `40104` |
| 6 | 加珠 | 复用上托盘结构的加珠路径 | `40105`（PLC 点表） |
| 7 | 上托盘/上坩埚 | 从方舱或料架 2 取托盘/坩埚到料架 1 | `40106` |
| 8 | 声共振上料 | 把托盘送入声共振工位 | `40107` |
| 9 | 声共振下料 | 声共振完成后取出托盘 | `40115` |

状态编码通常为：`0=未执行/空闲`、`1=执行中`、`2=执行完成`、`3=任务失败`。`40108` 是方舱内部阶段状态，不是命令 7 的完成寄存器；其值 1～7 表示外舱门、抽放气、内舱门和搬运等阶段。

### 4.3 命令 7：上托盘/上坩埚

命令 7 从 `40001` 开始写 11 个寄存器：

| 地址 | 内容 |
| --- | --- |
| `40001` | `7` |
| `40002` | 来源位置：PLC 线值 `1=方舱`、`2=料架2` |
| `40003` | 目标位置/回放位置，具体含义由 PLC 流程定义 |
| `40004` | 托盘类型：`1=4 槽`、`2=5 槽`、`3=6 槽` |
| `40005`～`40010` | 六个槽位的坩埚类型编码，未使用槽位写 `0` |
| `40011` | 加珠瓶来源；没有加珠瓶写 `0` |

设备包对外用 `0=方舱、1=料架2` 表示坩埚来源，只有在 Modbus 控制器边界转换为 PLC 线值 `1/2`。不能把工作流参数全局改成 PLC 线值。

命令 7 前的人工确认内容是：操作员已把托盘和坩埚放到料架 2，并确认托盘/坩埚规格和槽位。确认通过后，PLC 才驱动机器人搬运。

### 4.4 命令 3：扫码、称粉、加粉、加珠

命令 3 从 `40001` 开始写 81 个寄存器：

| 地址 | 内容 |
| --- | --- |
| `40001` | `3` |
| `40002` | 取坩埚/料罐位置；从外部人工放入时使用 `99` |
| `40003` | 称重完成后 PLC 把坩埚放回的位置 |
| `40004` 起 | 物料组，每组 5 个寄存器 |
| `40080` | 坩埚类型 `1..5` |
| `40081` | 球磨珠数量；无加珠瓶时写 `0` |

每组物料的字段顺序是：

```text
料架位置
目标质量 float32 低字
目标质量 float32 高字
容差 float32 低字
容差 float32 高字
```

PLC 点表列出了 15 组物料；旧 Qt 客户端历史实现最多写 10 组，设备包编码器和结果读取支持 15 组。OS 配方的重量单位是克，写 PLC 前转换为毫克；容差按目标重量计算为相对比例。

PLC 内部完成扫码绑定、打开/关闭天平门、机器人取放、称粉、加粉、加珠和称重后的坩埚回放。OS 不需要为“打开天平门”另发一个独立命令。

### 4.5 命令 8、等待和命令 9

命令 8 从 `40001` 开始写 21 个寄存器：

- `40001=8`；
- `40002` 为取托盘位置；
- `40003=2` 为目标流程位置；
- `40004` 起每组三个参数：加速度、频率、时间（秒），最多 6 组。

OS 页面以分钟输入声共振时间，设备包下发前转换成秒。命令 8 完成代表托盘已进入声共振工位，不代表振动工艺已经结束。工作流随后轮询 `40109`，等其变为完成，再发送命令 9。命令 9 使用：`40001=9、40002=1、40003=1`，完成状态为 `40115`。

### 4.6 状态和结果读取

OS/旧 Qt 会轮询 `40100`～`40116`。加粉结果另外读取 `40120`～`40189`：

| 地址范围 | 内容 |
| --- | --- |
| `40120`～`40149` | 15 个实际称量值，每个值占两个寄存器，IEEE-754 float32，低字在前 |
| `40150`～`40164` | 15 个加样结果，`1=OK`、`2=NG` |
| `40170`～`40189` | 扫码字符串，按 ASCII 读取，每寄存器低字节在前 |

底层设备动作可以读取目标槽位对应的扫码值、实际重量和结果码。当前料架 2 工作流对外返回扫码值和实际重量；如果只看到 `task_id`，说明调用的是旧业务兼容接口，而不是直接 PLC 动作结果契约。需要把每槽位的 OK/NG 结果呈现在 OS 时，应在动作结果类型和工作流返回值中继续暴露 `result_codes`。

## 5. OS 工作流的运行逻辑

当前主要工作流是“料架 2-加粉加珠声共振流程”。它的动作顺序如下：

1. **选择输入**：选择配方、托盘规格、坩埚规格、使用槽位、是否有加珠瓶、球磨珠数量和声共振参数。托盘规格决定可用槽位数，坩埚规格必须与托盘兼容。
2. **人工确认并上托盘**：操作员将托盘和坩埚放到料架 2，点击确认。原子工站调用命令 7，等待 `40106=2`。
3. **按槽位加粉和加珠**：OS 从所选配方得到物料名称、目标重量和容差，再从配方/料架目录得到每种物料的 PLC 料架位置。原子工站逐槽调用命令 3，等待 `40102`，读取扫码、实际重量和结果。
4. **人工确认并声共振上料**：确认加粉完成、托盘处于料架 1、声共振设备可用后，调用命令 8，等待 `40107=2`。
5. **等待声共振工艺完成**：只轮询 `40109`，不占用工站动作锁；振动期间 OS 可以调度其他不冲突任务。
6. **声共振下料**：`40109=2` 后调用命令 9，等待 `40115=2`。
7. **工作流结果**：返回动作成功状态、消息、扫码值、实际重量和声共振状态。设备包内部同时维护批次、坩埚和粉料账。

工作流中的人工确认是 OS 节点标记，不是 PLC 命令。人工确认只负责让操作者确认现场条件；真正让设备运动的是后续的 Modbus 写命令。

## 6. 配方、物料和料架数据逻辑

### 6.1 配方来源

`synthesis_catalog.py` 的配方读取顺序是：

1. 如果设置 `YB_SYNTHESIS_RECIPE_DIR`，读取该目录中的 `*.json`；
2. 否则读取设备包内的 `yb_sse_devices/data/recipes/` 快照；
3. 如果目录没有可解析配方，才使用少量兼容测试别名。

配方 JSON 中每个带 `weight` 的对象都被识别为物料行，读取字段：

```text
recipe_name
formula
synthesis_mass
n_ball_bead
<物料名>.weight
<物料名>.tolerance
<物料名>.pre-add
```

因此工作流不应写死“永远是 LiCl 和 P2S5”。不同配方可以包含不同物料；工作流只传递被选配方解析出的物料行。

### 6.2 料架来源

料架位置是安装状态，不是化学配方。设备包内的 `data/rackdata.json` 是可复制、可审计的快照。当前已确认的原始映射为：

```text
LiCl  -> 1
Li2S  -> 2
P2S5  -> 3
LiBr  -> 4
```

如果现场只是临时卸下 2 号位，不能直接用临时的空料架文件覆盖设备包快照。只有确认物理位置已经永久变更后，才使用同步脚本的 `--sync-rack` 更新快照，并重新做真机前检查。

### 6.3 同步旧上位机数据

只同步配方（默认行为）：

```powershell
& "C:\ProgramData\miniforge3\envs\unilabv2\python.exe" `
  scripts/sync_upper_station_data.py `
  "D:\yb_solidexperiment-260824\yb_solidexperiment-260824"
```

只有经过现场核对，确定要替换料架快照时才加：

```powershell

```

## 7. 开发逻辑和扩展方法

### 7.1 新增或修改配方

1. 在旧上位机 `recipes` 目录新增或修改 JSON；
2. 用同步脚本更新 `yb_sse_devices/data/recipes/`，或在受控部署中设置 `YB_SYNTHESIS_RECIPE_DIR`；
3. 确认配方里的每种物料在料架目录中都有位置；
4. 重新生成/发布工作流合同，使 OS 的配方枚举包含新配方；
5. 在本机仿真中验证目标重量、容差、结果读取和槽位校验。

### 7.2 新增托盘或坩埚规格

在 `synthesis_catalog.py` 中同时维护：

- 操作员显示名称；
- PLC 数字编码；
- 托盘槽位数；
- 托盘与坩埚的兼容关系。

命令 7 的六个槽位字段不是任务槽位编号，而是坩埚类型编码。未使用槽位必须写 `0`。任务槽位只表示本次使用哪些槽位，设备包负责把两者转换成 PLC 需要的六个字段。

### 7.3 修改 PLC 动作

建议按以下层次修改，不要在工作流里直接拼 Modbus 寄存器：

1. 在 `protocol/yb_synthesis_modbus.yaml` 更新协议合同；
2. 在 `modbus.py` 实现数值、浮点和字符串编码；
3. 在 `yb_synthesis_modbus_station/device.py` 实现一个完整动作：校验、写命令、轮询状态、解码结果；
4. 在 `yb_synthesis_atomic_station/device.py` 暴露 OS 原子动作和资源边界；
5. 在 `experiment_operations` 或 `workflows` 组合动作，并用人工确认标记表达现场确认点；
6. 更新工作流发布合同和测试。

### 7.4 直接 PLC 模式与旧业务接口

真实 PLC 的通讯表提供的是命令/状态寄存器，并没有旧 Qt 业务层的 TASK、POST、LOT 接口。直接模式下：

- OS 在本地生成批次标识和物料账；
- PLC 只接收命令 3/7/8/9 等寄存器报文；
- `create_batch()` 不应要求 PLC 创建 TASK；
- 旧的 `create_task()`、`start_task()`、`upload_cubic()` 等业务兼容动作只能在明确启用业务模拟器或旧业务后端时使用。

## 8. 仿真、真机和启动方式

### 8.1 本机仿真

本机仿真使用设备包自己的 Modbus 仿真器，地址为 `127.0.0.1:5020`，启动图为 `deployment/graphs/local-sim.json`。仿真器模拟寄存器、机器人动作、扫码、称量和声共振状态，不会驱动真实设备。

### 8.2 真机启动前检查

真机图为 `deployment/graphs/real-plc.json`。运行前必须逐项确认：

1. OS 实际加载的是 `real-plc.json`，不是 `local-sim.json`；
2. PLC 端口和 Unit ID 已通过现场或通讯抓包确认；
3. PLC 在远程自动模式，且没有旧上位机同时写命令；
4. 机器人安全点、急停、门、光栅、舱门和天平状态满足；
5. 托盘规格、坩埚规格、任务槽位和料架位置与实物一致；
6. 日志中能看到命令寄存器写入和对应 `401xx` 状态变化；
7. 首次联调先使用空载/维护模式，并由现场人员负责机械安全确认。

当前配置里的 `192.168.1.10:502`、Unit ID `1` 只能作为部署候选值。未经现场确认，不应发送命令 3、7、8、9。

### 8.3 停止和恢复

发生通讯异常或 PLC 状态不再变化时：

1. 先停止 OS 工作流调度，不重复发送同一命令；
2. 读取并记录最后一条命令、状态寄存器、报警和机器人状态；
3. 按现场 SOP 处理机械安全和残留物料；
4. 确认 PLC/机器人回到安全待机后再恢复；
5. 不通过清空寄存器或重启进程代替 PLC 故障复位。

## 9. 常见问题和排障

### OS 显示已连接，但动作不动

先检查 OS 是否使用了正确启动图、PLC 是否允许远程自动、Unit ID/端口是否正确，以及是否有旧 Qt 上位机或 HMI 同时占用流程。

### `40108` 变化但命令 7 没完成

`40108` 是方舱内部阶段状态，不能代替 `40106`。命令 7 的完成判断看 `40106=2`；同时查看门、抽放气、机器人和互锁报警。

### 配方能选但无法下发命令 3

检查配方每种物料是否存在于料架映射，料架位置是否是 PLC 能识别的编号，重量和容差是否为有限数值，以及槽位是否属于所选托盘规格。

### 称重后没有结果

检查 `40102` 是否从 1 变成 2/3；成功后再读取 `40120`～`40189`。扫码格式和 PLC 的专用失败寄存器目前没有完整公开，空二维码、超时和任务失败都要保留原始日志。

### 仿真通过，真机仍不能运行

仿真只证明设备包编码、状态机和工作流逻辑；它不能证明现场端口、Unit ID、机器人点位、物料实际位置、门互锁或 PLC 当前程序状态正确。真机联调必须单独完成。

## 10. 当前已知限制

- PLC 点表支持 15 组物料；旧 Qt 客户端历史路径只写 10 组，OS 设备包按协议支持 15 组。
- PLC 工程确认了主流程和互锁，但部分超时、报警复位和扫码失败细节仍需 AutoShop 在线监控确认。
- `40105`/`40106` 在旧 Qt 客户端的状态选择与点表存在差异，开发时以 PLC 点表和实际 PLC 状态为准，不要只复制旧客户端的状态索引。
- Unit ID、Modbus 端口、D/R 到 Holding Register 的现场映射以及 QR 字符串校验规则仍需现场确认。
- `crucible_return_positions` 和 `powder_rack_positions` 是安装位置参数，不应伪装成 PLC 已公开的配方字段；没有确认现场位置时，真机流程应保持阻止下发。
