# YB 合成原子动作

合成上位机/PLC 的协议动作是底层接口；原子动作还要等到完成反馈后，才更新物料位置。
当前设备包按以下边界拆分。边界按“可独立追踪的连续业务/物理过程”确定，不按单个
PLC 寄存器写入拆分：

| 原子动作 | 连续过程 | 完成后的物料位置 |
| --- | --- | --- |
| `load_big_crucible` | 从方舱或坩埚架取大坩埚，方舱来源同时完成关门 | 来源位 → 合成位 |
| `confirm_recipe` | 确认预加料的实际重量和配方参数 | 不移动物料 |
| `dose_recipe` | PLC `CMD_SAMPLE` 一次完成内部扫码绑定、称粉、加粉和加珠 | 粉料/球磨珠 → 大坩埚 |
| `start_resonance` | 声共振上料并运行到完成反馈 | 大坩埚仍在共振设备内 |
| `unload_resonance` | 声共振下料、结束握手并提交位置账 | 合成位 → 装瓶位 |
| `scan_bottle` | 扫大坩埚二维码并完成装瓶交接 | 大坩埚仍在装瓶位 |
| `prepare_post` | 建立 POST、扫描并确认 LOT | 装瓶位 → 后处理队列 |
| `assign_small_crucible` | 扫 LOT 并分配小坩埚 | 小坩埚架 → 待烧结 |
| `confirm_firing_schedule` | 确认烧结计划 | 不移动物料 |
| `start_sintering` | 启动烧结并等待仿真/PLC完成 | 小坩埚仍在炉内 |
| `unload_sintered` | 取出炉内小坩埚并提交位置账 | 炉位 → 待入库位 |
| `store_fired_material` | 扫瓶码并入库 | 待入库位 → 成品库 |

`create_batch` 只负责上传配方、创建 TASK、启动 TASK 和建立初始账，不代表物理移动。
每个原子动作都绑定一个 TASK/POST；不同批次不能交错执行。动作失败、超时或位置不匹配时，
账仍停留在上一个稳定位置，避免重复扣料或重复入库。

实现位于 `yb_sse_devices/synthesis_atomic.py`，默认使用设备包内的 Modbus PLC 模型和
业务仿真。底层称粉会真实经过 `CMD_SAMPLE`、内部扫码绑定和完成状态读取；上层 TASK/POST/LOT
`CMD_SAMPLE` 在 PLC 协议中本来就是扫码、称粉和加珠的组合命令，因此这三个底层步骤
保持一个原子节点，不能为了增加节点而虚构一个独立扫码寄存器。上层 TASK/POST/LOT 流程
使用设备包已有的业务仿真，不新增 IO 表中没有的寄存器。

当前 `store_fired_material` 会调用已有的 `scan_bottle_to_stock` 业务接口；真实现场若有独立
扫码枪/入库协议，后续只需替换这一层，不改变前面的原子动作边界。
