# 设备包规范整改记录

本分支按设备包模板与 SZLab 的目录职责整理。可注册的对象在源码中只保留一份定义，旧路径只做兼容转发。

## 十项整改

1. **单一 PLC 根设备**：仿真、联调和生产原子图只挂一个 `yb_synthesis_atomic_station_01`；直接 Modbus 图单独保留，避免同一启动图重复接管 PLC。
2. **发布合同一致**：四个工作流都在 `workflow_publications/<workflow_uuid>/` 生成 manifest 和 contract，索引记录工作流 UUID、合同 UUID、版本和修订。
3. **动作结果有合同**：设备动作按 `TypedDict` 返回字段，原子称粉边界明确返回 accepted、success、状态码、二维码、重量和物料引用。
4. **清理本机路径**：协议只保留来源文件名、摘要和说明；运行图和包内源码不引用个人电脑绝对路径。
5. **设备一目录**：设备实现位于 `yb_sse_devices/devices/<device_id>/`，设备 ID 与目录保持稳定 snake_case。
6. **资源一目录**：物料、料架和台面位于 `yb_sse_devices/resources/<resource_id>/`，每个资源目录有自己的 `resource.py`。
7. **资源 ID 稳定**：工作流和启动图只引用稳定资源 ID，不再混用旧类名、显示名和临时路径。
8. **自动检查和构建**：`scripts/check-package.sh` 检查目录、UUID、启动图、合同和本机路径；`scripts/build-package.sh` 在临时干净目录生成发布归档。
9. **包级测试**：`tests/test_package_delivery.py` 覆盖 manifest、启动图、合同和发布路径；协议、动作、PLC 模型和 Modbus-Sim 继续由原有测试覆盖。
10. **文档和来源**：README 说明 OS、设备包、PLC 和两种仿真的关系；`protocol/yb_synthesis_modbus.yaml` 记录 IO 表、Qt 上位机和 PLC 工程备份的来源及摘要。

## 使用原则

模板目录中的 `my-device-package/` 表示 Python import package。YB 对应的目录是
`yb_sse_devices/`，所以 `yb_sse_devices/devices/`、`yb_sse_devices/resources/` 和
`yb_sse_devices/workflows/` 已经是包内一级目录；它们不应再移动到仓库根。当前 OS 的
PackageCatalog 只扫描这个 import package，工作流清单也要求以
`yb_sse_devices/workflows/*.py` 声明来源。

- `simulation.json` 验证业务顺序、物料位置账和故障恢复。
- `integration.json` 验证 Modbus TCP 帧和 PLC 状态反馈，必须检查 JSONL 通讯日志。
- `production-atomic.json` 是连接真实 PLC 的原子设备图模板；接入现场前必须再次核对 IP、端口、Unit ID、IO 表和安全互锁。
- OS 负责排队、调度、资源锁和任务记录；设备包负责设备动作、物料资源和工作流定义。
